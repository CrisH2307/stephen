## Verified fine

- **The key never appears in argv.** It travels only on the stdin of `security -i`. The probe confirmed this: keys containing quotes, spaces or newlines, or a newline followed by a second command, are rejected by `API_KEY_RE` (`/^[A-Za-z0-9_-]{20,256}$/`, no `m` flag) before anything runs. A key made only of dashes (`-----…`) is accepted. That is harmless because it is the optarg of `-w`.
- **The key is scrubbed from every output path.** This covers the ElevenLabs error body (`scrubKey` plus control-character stripping, capped at 200 characters), network errors, 401 messages (`redactKey`), `security` stderr, `voice-key status` (last 4 characters only), `TtsPlan` (redacted) and the `announce` audit entry (text and provider only). Nothing key-related reaches a tool result.
- **Key file checks.** `stat` follows symlinks, so the target's owner and mode are what get checked. `mode & 0o077` rejects group- or other-readable files. Only regular files are accepted.
- **Temp audio files.** Each lives in a `mkdtemp` folder (0700) as a file with mode 0600 and the `wx` flag, and is removed in `finally` on normal and cancel paths.
- **The `say` provider** gets its text on stdin, never argv. Every child is spawned without a shell, and `redirect: 'error'` is set on fetch.
- **`announce` is registered only with `serve --voice`.** `serve-args.ts:23` sets it, `cli.ts:99` passes it through, and `announce.ts:48` checks it. The listener's MCP config has both `--confirm dialog` and `--voice` (`claude.ts:127`).
- **`announce` limits hold.** The rate limit is pushed before any `await`, so it holds under concurrent calls. Each call waits at most 8 s and is then cancelled, and it never blocks the event loop.
- **Nothing spoken counts as approval.** Confirmations are macOS dialogs (`listener.ts:19`, `--confirm dialog`). If `announce` speaks the wake or stop phrase during a run, it can only cancel that run (`listener.ts:244-250`).
- **Esc, PTT and the stop phrase** call `assistant.cancel()`, which kills the whole group through `killGroup(-pid)` (`claude.ts:240-245`). Claude runs `detached` and `afplay` from `announce` inherits its group. The SIGKILL timer is cleared when the run closes, so a reused pid is never signalled.
- **Quiet-while-playing never hides a reply.** The reply or error, including denials, is printed with `status` before the decision to speak or not (`assistant.ts:69`).
- **Framing limits.** Lines over 4 KiB are dropped and resync at the next newline (probe), and zod rejects mistyped fields. On the Swift side, the server checks `getpeereid` UID, socket and directory permissions are 0600 and 0700 (umask plus chmod), and the socket is unlinked on stop only when its inode is still ours.
- **`install-helper`.** Every command is an argv array (paths with spaces are fine). `open -a <app> --args --home <home>` is used. Signing is ad hoc (`--sign -`) with `--identifier dev.stephen.helper`. TCC binds an ad-hoc grant to the cdhash, so another app that copies the identifier does not inherit Input Monitoring. The catch is that the user must grant it again after each rebuild.
