## Verified fine (attacked and held)

- **Host normalization** (`u1-hosts.mjs`): `MAIL.GOOGLE.COM.` is the same host; `mail.google.com@evil.com`, `0x7f.1`, `2130706433`, `[::1]` and the punycode homoglyph `xn--mil-8cd.google.com` all hit the data rule; `google.com/url?q=` hits the open-endpoint rule.
- **After taint:** query, fragment and long path to another host prompt (`p1` B2). Google Docs per-document scope prompts (`p9` control).
- **`find` and `wait_for` queries** run in the isolated world, so page scripts never see them.
- **`type` never sends key events.** Control characters are refused, `\n`/`\t` are refused in single-line fields, and `type=password`, "Password" and "Passphrase" fields are refused and redacted (`p3`).
- **Blocked targets:** `tab_open` and `reload` on a blocked site are denied (`p8`).
- **`beforeunload` on navigate** is surfaced as a dialog (`p7` a0).
- **Wrapper escaping:** `wrapUntrusted` escapes the delimiter, and tab lists and outcome facts are wrapped.
- **Parallel calls on one tab:** `type` + `click` + `snapshot` are serialized correctly (`p5` step 2).
- **Hung tab** (multi-process): snapshot times out cleanly at 15 s, `tabs_list` returns in 1.5 s, `tab_close` works.
- **Browser killed:** the next `tab_open` relaunches transparently, and old tab ids return `TAB_NOT_FOUND`.
- **Server restart** reattaches to the running agent Chrome and its tabs in 57 ms (`p7` b1). Tab ids are renumbered after a restart; old refs from before the restart may name other elements, but the gate always judges the live element.
- **Zen launch:** `--remote-debugging-port 0` is supported (atomic port: `if (port === 0) port = -1`), and the listening line is printed with `Cu.printStderr(\`WebDriver BiDi listening on …\`)`, which does not depend on the `dump` pref. Both are in [RemoteAgent.sys.mjs](https://raw.githubusercontent.com/mozilla-firefox/firefox/main/remote/components/RemoteAgent.sys.mjs) and [WebDriverBiDi.sys.mjs](https://raw.githubusercontent.com/mozilla-firefox/firefox/main/remote/webdriver-bidi/WebDriverBiDi.sys.mjs). browser-hub's regex matches the line; puppeteer uses the same regex (`@puppeteer/browsers/src/launch.ts`).
- **Recommended prefs** are set on the default branch and "never written to the profile's prefs.js", so a real-profile session cannot persist them. The `user.js` block is extra protection; it stays in the profile permanently but is harmless and documented.
- **Zen profiles path:** the vendor dir is lowercase `zen` on other OSes (Linux `~/.zen`, Windows `%APPDATA%/zen/Profiles`, per [docs.zen-browser.app](https://docs.zen-browser.app/llms.txt)), which is consistent with `~/Library/Application Support/zen`. APFS is case-insensitive by default.
- **Chrome real mode:** Chrome 144+ requires the `chrome://inspect/#remote-debugging` toggle and shows a per-connection Allow dialog ([Chrome blog](https://developer.chrome.com/blog/chrome-devtools-mcp-debug-your-browser-session)), so one long-lived connection is correct. Chrome 136+ ignores `--remote-debugging-port` on the default data dir ([Chrome blog](https://developer.chrome.com/blog/remote-debugging-port)), but agent mode always uses its own `--user-data-dir`.
- **Never closes the browser:** only `disconnect()` is called, for both Chrome and Zen.
